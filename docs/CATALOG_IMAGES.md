# Catalog image stabilization

The 72 synthetic products use original repository-authored geometric accessory illustrations. Editable SVGs and 512×512 PNGs are in `apps/mobile/assets/catalog`; their source/license statement is [here](../apps/mobile/assets/catalog/README.md). The repository MIT license applies. No retailer photography, external stock assets, brand marks or generative service credits were used. Some closely related fixtures share motifs; these are demo illustrations, not real merchandise photography or visual verification.

The existing `imageUrl` schema is unchanged. `catalog://demo/E01.png` is a logical bundled asset identifier resolved by the mobile static manifest, not a public HTTP endpoint. Future clients need an equivalent resolver. Metro bundles PNG assets for release exports; the development client fetches those bundled assets from Metro. Catalog artwork is independent of portrait uploads, YouCam product assets and VTO results. All fixture `vtoAssetUrl` values remain null.

`ProductImage` serves search/anchor results, comparisons, and selected/saved/shortlisted/rejected summary thumbnails. It reserves a square frame (112×112 logical pixels in summary), uses explicit 100% image dimensions and `contain`, and never stretches imagery. Loading shows a spinner; a missing/unsupported source shows a stable fallback; a native load failure shows an explicit retry button. Retry remounts only the image attempt. Source changes reset state, so stale failures cannot obscure another product. Image state does not affect shopping state or ranking.

The intrinsic-size regression found on Android is covered by a rendered-component test: absolute positioning alone left the bundled 512px intrinsic dimensions active, clipping artwork and blanking thumbnails. Explicit width and height fix this. Portable resolver/lifecycle tests are in `tests/catalog-images.test.ts`; rendered host-component tests are under `apps/mobile/src/__tests__` to keep React Native globals isolated from backend typechecks. Native behavior is separately verified on Samsung.

Migration `003_catalog_images.sql` repairs only exact original `.invalid` fixture URLs for the 72 known IDs. It changes no other product facts and leaves approved/custom sources untouched. Run the standard migration command for existing databases; `npm run db:local` applies it to local development. Old persisted/replayed responses also resolve their exact original placeholder IDs to bundled images. Existing migration checksums, seeding semantics and session records remain intact.

Regenerate assets with `node --import tsx scripts/generate-catalog-art.mts`, then format the generated manifest. Replacement imagery should be approved/licensed, category-appropriate and padded square artwork. Never substitute these illustrations for approved live YouCam rendering assets. See [VALIDATION.md](VALIDATION.md) for completed checks. M9 has not started; the live-YouCam final-submission gate remains OPEN.
